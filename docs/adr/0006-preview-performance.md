# ADR-0006：预览降采样与渲染性能

- 状态：Accepted
- 日期：2026-10-28

## 背景

“实时预览”要求参数变化后快速反馈，但原图可能是 6000×4000。直接在原图上重绘会让主线程长时间阻塞，批量同步缩略图更会放大问题。

## 决策

### 三级位图

| 用途 | 长边上限 | 生命周期 |
| --- | --- | --- |
| 缩略图 | 160px | 解码后缓存，随批次存在 |
| 预览图 | 2048px | 仅当前选中图 + 最近使用的少量图 |
| 导出图 | 原分辨率 | 导出时临时解码，用完立即释放 |

### 解码策略

- 导入时只解码缩略图，不保留全分辨率位图。
- 选中某张图时才解码其预览图；切换图片时释放上一张。
- 导出时按并发上限临时解码原图，编码后 `close()`。
- 使用 `createImageBitmap`，并处理 EXIF 方向；不可用时回退 `<img>` + canvas。

### 渲染调度

- 参数变更：防抖 80–120ms + `requestAnimationFrame` 合并。
- 当前大图优先重绘，缩略图其次。
- 不可见缩略图（滚动区域外）用 `IntersectionObserver` 延迟渲染。
- 拖拽缩放/平移不触发重新计算平铺，只变换已渲染位图。

### 批量导出

- 在 Web Worker 中用 `OffscreenCanvas` 渲染与编码，避免阻塞 UI。
- 主线程只负责传递 `File`/`ArrayBuffer` 与汇总进度。
- 不支持 OffscreenCanvas/Worker 时，降级为主线程顺序导出（UI 可能短暂卡顿）。

### 保护阈值

- 渲染前估算 Tile 数；超过 20,000 时提示“水印过密”并阻止导出。
- 预览图长边超过 2048 时继续降到 2048，不随 DPR 无限放大。

## 理由

- 预览只需要“看得清布局”，不需要原图精度；导出才需要。
- 只保留缩略图，避免 50 张大图同时解码造成内存爆炸。
- Worker 隔离编码是保持 UI 可交互的最直接手段。

## 后果

- 预览与导出存在分辨率差异，必须通过 ADR-0003 的相对参数保证视觉一致。
- 需要维护位图缓存与释放逻辑，否则会泄漏 GPU/内存。
- 首屏导入 50 张时，仍需控制缩略图解码并发（建议 4–6）。
- 低端设备上降级路径可能触发长任务，需要用进度提示兜底。
