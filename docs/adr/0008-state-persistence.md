# ADR-0008：状态模型与参数持久化

- 状态：Accepted
- 日期：2026-10-28

## 背景

界面由图片列表、预览、参数、导出四块组成，且参数变化要同时驱动预览与缩略图。参数还需要在刷新后恢复。需要一个清晰、可测试的状态边界。

## 决策

### Store 分片（Zustand）

| Slice | 内容 | 是否持久化 |
| --- | --- | --- |
| `batch` | 素材元数据、状态、当前选中 id | 否 |
| `spec` | `WatermarkSpec` | 是 |
| `preview` | 缩放、平移、当前位图引用 | 否 |
| `export` | 任务状态、进度、结果 | 否 |

- 组件通过 selector 订阅最小切片，避免参数变化导致整树重渲染。
- 位图（`ImageBitmap`）不放进可序列化的 store 快照，单独用缓存管理。

### 持久化

- 键名：`watermark:spec:v1`。
- 只存 `spec`，写入防抖 300ms。
- 读取时逐字段校验并钳制到合法范围；缺失字段用默认值补齐；版本不符则丢弃。
- “恢复默认”写入默认值，而不是删除键（保证下次打开仍是默认）。
- 素材、缩放、导出结果、导出质量不持久化。

### 导出快照

- 点击导出时对 `spec` 深拷贝，传入导出任务。
- 导出任务不读取 store 的实时值。
- 导出期间禁用会改变批次组成的操作（导入/清空），但允许调参（只影响下次）。

## 理由

- 单一 Spec + 单向数据流，最容易保证“调一次、全部同步”。
- 只持久化参数，符合隐私预期，也避免把大文件塞进 localStorage。
- 版本化键名 + 校验，能在字段演进时安全回退。

## 后果

- 需要为 `spec` 写序列化/反序列化与钳制函数，并配单元测试。
- 刷新后批次清空是明确行为，用户需要重新导入。
- 导出与调参可以并发，但结果以快照为准，UI 需要提示“本次导出使用开始时的参数”。
- 若未来增加预设，可在 v2 键名下扩展，不破坏现有数据。
