# ADR-0005：导出管线与交付方式

- 状态：Accepted
- 日期：2026-10-28

## 背景

导出需要同时满足：保持原格式、控制质量、单张与批量两种交付、进度与取消、去除元数据。不同格式的能力不同（JPEG/WebP 有损，PNG 无损）。

## 决策

### 格式

- 跟随原图：JPEG→JPEG、PNG→PNG、WebP→WebP。
- JPEG / WebP 提供质量滑块 0.60–1.00，默认 0.92；PNG 隐藏质量控件。
- 通过 `canvas.toBlob(type, quality)` 编码。
- 若浏览器不支持 WebP 编码，回退 PNG 并明确提示。

### 元数据

- 不保留 EXIF/GPS。Canvas 重编码天然丢弃元数据，这是隐私上的正向副作用。
- EXIF 方向在解码阶段已烧录进像素，因此导出图方向正确。

### 命名

- 单张：`<basename>-watermarked.<ext>`。
- 重名：追加 `-1`、`-2`，保留扩展名。
- ZIP：`watermarked-<YYYYMMDD-HHmmss>.zip`，包内平铺，不建子目录。

### 交付方式（Delivery Mode）

- 单张：`direct`，直接触发下载。
- 多张：两个并列按钮：
  - `zip`：用 `fflate` 在内存中打包后下载。
  - `per-file`：逐张触发下载，间隔调度，避免浏览器拦截。
- 不做“根据数量自动切换”，把选择权交给用户。

### 进度与取消

- 显示“已完成 / 总数 + 当前文件名”，进度用 `aria-live` 播报。
- 可取消：设置取消标志，停止调度后续素材。
- 取消后：`zip` 不产出文件；`per-file` 已触发的下载保留。
- 导出在 Worker 中执行；不支持时降级主线程顺序导出。

### 并发与内存

- 导出并发 ≤ 2（默认 1）。
- 每张：解码 → 渲染 → 编码 → 释放位图（`bitmap.close()`）。
- 任何时刻内存中不同时保留超过 2 张全分辨率位图。

## 理由

- 保持原格式最符合用户预期，避免无意中改变文件类型或丢失透明通道。
- 两个按钮比自动分流更可预期，也避免“批量打包但用户只想要单张”的错配。
- 冻结 Spec + 逐张释放，是控制批量内存峰值的关键。

## 后果

- ZIP 需要额外依赖 `fflate`（体积小、无 DOM 依赖）。
- `per-file` 在部分浏览器会触发“是否允许多文件下载”的权限提示。
- 去除元数据意味着无法保留拍摄信息；这是与隐私目标一致的取舍。
- PNG 导出体积可能很大，UI 需提示但不阻止。
- 编码失败（内存不足、格式不支持）必须计入失败汇总，不能静默丢弃。
